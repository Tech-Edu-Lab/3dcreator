# 正投影図 3Dクリエイター

中学校技術科（材料と加工の技術）向けの Web アプリです。
**第三角法による正投影図**を方眼用紙にかき、その用紙を読みこませると、360度回せる 3D モデルになります。
板の厚さやつなぎ目を考えていない図面は立体にせず、どこをどう直せばよいかを赤ペンのように示します。

- インストール不要。`dist/index.html` の **1ファイルだけ**で動きます（ネット接続なしでも動作）。
- 図面や写真は端末の中だけで処理します。外部には送信しません。

## 開き方

- **ブラウザで開く**：<https://tech-edu-lab.github.io/3dcreator/>
- **1ファイルで配る**：[`dist/index.html`](dist/index.html) をダウンロードして、ブラウザ（Chrome / Edge / Safari）で開くだけです。
  学校のサーバ、共有フォルダ、Google Classroom などに `index.html` を1つ置けば配布できます。

同じ Wi-Fi のタブレットで試すときは、次のコマンドで配信できます。

```
npm run serve      # http://localhost:8080/
```

## 4つの条件と、このアプリでの実現方法

| 条件 | 実現方法 |
|---|---|
| ① 正投影図を記入する方眼用紙をフォーマットとして出力 | 「1 用紙を出す」で 5mm 方眼の用紙を **PDF / PNG / 印刷** で出力。標準は **A3**（横・縦）、小さな作品用に A4 も3種類。四すみに位置合わせ用のマーク、左上に設定コードが入る |
| ② ①のフォーマットを読みこむと、360度回転できる 3D モデルを出力 | 「2 図面を読みこむ」で写真・スキャン画像を選ぶ（はりつけ・ドラッグ＆ドロップも可）。傾き・回転・ゆがみを自動で補正して線を読み取り、立体にする。ドラッグで自由に回転、「自動で回す」「ばらして見る」も可 |
| ③ STL または GLB で保存 | 「STLで保存」（3Dプリンタ用。全体が1つの閉じた形、単位 mm）、「GLBで保存」（板ごとに分かれた色つきモデル、単位 m） |
| ④ 板厚を考えていない線（組み立て方が分からない）は出力せず、修正を促す | 「板厚チェック」。すべての部品が指定した厚さの板になっていて、板どうしの境目が決まるときだけ出力する。だめなときは 3D も保存ボタンも出さず、図面の該当部分を赤くして直し方を表示。線1本でかいたたな板のように、板のはしとも読めてしまう線も、出力せずにたしかめる |

## マスと寸法の考え方

板の厚さ（12mm）と、きりのよい寸法（10mm きざみ）は、同じ方眼にはぴったり乗りません。
しかも、外形を 220mm にすれば内側は 220−24＝196mm、内のりを 300mm にすれば外形は 300＋24＝324mm と、
板の厚さを正しく考えるほど半端な長さが生まれます。そこで、このアプリでは **図は「形」と「およその大きさ」、長さは数字** で決めます。

1. **1マス＝10mm** で数えてかく（220mm なら 22マス。1/10 でかくときと同じ数え方）。
2. **板の厚さは 1マス** でかく。アプリが、板の厚さのマスだけを本当の厚さ（12mm）に読みかえる。
3. **全体の大きさはマスの数どおり**（外形基準）。22マスなら 220mm。のこりは自動で計算される。
   例：はば22マスで両がわが側板 → `12 ＋ 196 ＋ 12 ＝ 220`
4. **きっちり決めたい所は、画面で数字を入れる**。図はかき直さなくてよい。
   例：内のりを 300 にしたい → あいだの数字を 300 にする → `12 ＋ 300 ＋ 12 ＝ 324`

立体が表示されると、右がわに「寸法（mm）」のらんが出ます。はば・高さ・奥行きごとに、上のようなたし算の形でならびます。

- 茶色の数字は板の厚さで、変えられません。
- 点線のわくの数字は自動計算です。数字を入れると実線のわくになり、その数字に固定されます。消すと自動にもどります。
- 「＝」の右は全体の大きさです。ここを変えると、固定していない所が合わせて変わります。
- 数字にカーソルを合わせると、図面のどの部分の長さかが青い帯で示されます。
- 部品表・STL・GLB は、この数字どおりの大きさになります。

1マスの大きさ（10mm）、板の厚さ（9〜20mm）、板の厚さを何マスでかくかは、「1 用紙を出す」で変えられます。

## かくれ線のあつかい

かくれ線（破線）をどこまでかかせるかは、設定でえらべます（画面の「かくれ線」と、「1 用紙を出す」の中。用紙のコードにも入ります）。

| 設定 | 生徒がかくもの | アプリの読み方 |
|---|---|---|
| **必要なものだけ**（標準） | 見える線は全部。かくれ線は、ほかの板にかくれた板や、見えないつなぎ目だけ | かいていないかくれ線はアプリがおぎない、図面に**緑の破線**で重ねて見せる |
| **全部かく** | 見える線も、見えない辺も全部（正投影図の練習） | かくれ線が1本でもたりないと「対応する線がない」と伝える |

「必要なものだけ」のときは、次のように読みます。

- **見える線（実線）は、3つの図ですべて合っていること。** かいてあるかくれ線も、立体の辺と合っていること（合わなければ、その線を赤くして伝えます）。
- **線のない所には、何もない。** ほかの板にかくれて、3つの図のどこにも線が出ない板（天板のあるたなの背板、いすの後ろがわの幕板など）は、かくれ線でかかないと立体に入りません。
- **板は、見えない所では、ほかの板に当たるまでのびている。** とちゅうで止まる板は、そのはしをかくれ線でかきます。
- **板の厚さは、どこかの図に表れていること。** 板を横から見た面が見えているか、かくれ線で厚さがかいてあるか、のどちらかが必要です。

それでも決まらないときは、立体を出さずにたずねます。

| たずねる場面 | 画面に出るもの |
|---|---|
| 見えない所の組み立て方が、いく通りか考えられる（例：底板が背板の下までのびているのか、背板が底板の後ろまで下りているのか） | 決まらない所を赤くぬり、**考えられるかくれ線をオレンジの破線**で示す。作品に合うものをかくれ線でかくと決まる |
| 線1本が、板のはしとも、厚さをかきわすれた板（たな板など）とも読める | その線を赤くし、「厚さ1マスの長方形でかく」か「板のはしをかくれ線でかく」かを伝える |
| 同じ平面にならんだ2枚の板のつなぎ目が、1つの図にしか出ていない | つなぎ目の線を赤くし、つなぎ目のかくれ線の場所を示す |
| 広い面だけがかかれていて、厚さがどこにも表れていない板がある | その板を赤くぬり、厚さをかくれ線でかくよう伝える |
| 板が多く、見えない所の決め方が多すぎる | かくれ線をかきたすよう伝える（全部かけば、かならず読めます） |

授業では **「右側面図に、側板にかくれた板（底板・背板・たな板など）をかくれ線でかく」** と教えるのがおすすめです。
本立て・たな・小物入れ・いす・箱など、よくある作品18種類でためしたところ、右側面図のかくれ線だけで、どれも元のとおりの立体になりました（`test/designs.test.js`）。

## 授業での使い方

1. **先生**：「1 用紙を出す」で、用紙の種類（標準は A3 横）・1マスの大きさ（標準 10mm）・板の厚さ（標準 12mm）を決めて、PDF を印刷する。
2. **生徒**：用紙に正面図・平面図・右側面図をかく（板の厚さは 1マスで）。
3. **生徒**：用紙を真上から撮影（またはスキャン）して、「2 図面を読みこむ」で読みこませる。
   - 図面は画面の方眼にデジタル化されます。読み取った線が青で写真に重なるので、写真とちがうところは、画面の道具（実線・かくれ線・消しゴム）で直せます。
   - 実線か破線かはっきり読めなかった線は、オレンジ色で示されます。
4. 図面が正しければ立体が表示されます。直すところがあれば、赤ペンのコメントが出ます。
5. **生徒**：「寸法（mm）」のらんで、きっちり決めたい長さを数字で入れる。部品表で、板1枚ずつの大きさをたしかめる。

用紙を使わず、画面の方眼に直接かくこともできます（方眼の交点から交点へドラッグ）。
用紙の設定（種類・1マスの大きさ・板の厚さ・板厚チェックの有無・かくれ線のかき方）は用紙左上のコードに入っているので、読みこむと自動で合います。

### 図面のかき方のきまり（用紙にも印刷されます）

1. 線は方眼の線の上に、定規でこくかく
2. 見える線は実線でかく
3. 見えないつなぎ目や、かくれた板は破線（かくれ線）でかく
   （かくれ線を「全部かく」設定の用紙では、2・3 が「見える線は実線、見えない線は破線」になります）
4. 1マスは 10mm。ただし板の厚さ（12mm）は 1マスでかく
5. 板と板のつなぎ目にも線をかく
6. 平面図は正面図の真上、右側面図は真横に、位置をそろえてかく
7. 四すみの ■ マークはよごさない・折らない

「見本をひらく」から、正しい図面（本立て）と、直すところのある図面3種類（かくれ線がたりない／板の厚さを考えていない／つなぎ目がない）を開けます。
見本は、かくれ線の設定に合わせて変わります（「必要なものだけ」では、かくれ線は底板の上の面の1本だけ）。

## 点検の内容

読みこんだ図面は、次の順に点検します。問題が見つかった段階で止まり、立体は出力しません。

| 段階 | 伝える内容の例 |
|---|---|
| 図のかき方 | 図がない／線がとぎれている／図からはなれた線がある／正面図と平面図のはばがちがう／平面図が右に2マスずれている／奥行きがちがう |
| 図どうしの対応（かくれ線を「全部かく」設定のとき） | 正面図の線に対応する線が平面図にない（かくれ線のかきわすれ）／平面図と右側面図で手前と奥が逆 |
| 立体として成り立つか | この線は見えないのでかくれ線にする／この線は見えるので実線にする／立体のどこにもあたらない線がある／見える線どうしが合わない |
| 見えない所（かくれ線が「必要なものだけ」の設定のとき） | 見えない所の形が決まらない／板のはしか、厚さのない線か決まらない／厚さの分からない板がある／かくれ線がたりなくて決めきれない（上の「かくれ線のあつかい」） |
| 板厚チェック | 板の厚さがかかれていない（かたまりになっている）／板と板のつなぎ目がかかれていない／板の厚さよりうすい／ほかの板にふれていない板がある |

### 板厚チェックの考え方

- 図面から立体を求めたあと、部品（線で区切られたかたまり）を1つずつ調べます。
- **板**＝ある1方向の厚さがちょうど指定のマス数で、その方向にまっすぐな形（切り欠きがあってもよい）。
- 板厚より厚い「かたまり」があれば **板の厚さがかかれていない**、板がいくつかつながった形（L字・コの字・わく）なら **つなぎ目がかかれていない**（＝どの板がどこまでのびるか分からず、組み立て方が決まらない）と判定します。
- 「板厚チェック」のチェックを外すと、板でない立体（段のあるブロックなど、正投影図の練習問題）も立体にできます。

図面から立体を求める方法は [src/core/solver.js](src/core/solver.js) の先頭に、かくれ線がはぶかれた図面の読み方は [src/core/lenient.js](src/core/lenient.js) の先頭に、図のかき方のきまりは [src/core/render.js](src/core/render.js) の先頭に書いてあります。

## できないこと・注意

- **水平・垂直の線だけ**に対応しています。ななめの線・曲線（側板をななめに切る形など）は、いまは立体にできません。
- 板の厚さは、1つの作品で1種類だけです（背板だけうすい合板、などは表せません）。
- 数字を入れていない所の長さは、マスの数から自動で割りふられます。たな板で分かれた2つのすき間などは、1mm 単位に丸めて配分します。
- かくれ線が「必要なものだけ」の設定では、**図面にかいていないことは、アプリには伝わりません。** かくれた板をかきわすれると、その板のない立体が「できました」と表示されます（天板のあるたなの背板など）。立体を回し、部品表の枚数を見て、作品のとおりかをたしかめさせてください。立体の下にも、その注意が出ます。
- 同じ設定で、平行な2枚の板のあいだに、板の厚さとちょうど同じはばのすき間がある作品は、すき間か板かを読み分けられないことがあります。そのときは、かくれ線を全部かくと正しく読めます。
- 「必要なものだけ」の読み方は、よくある作品18種類と、でたらめに組んだ板の作品（数百とおり）でたしかめたものです。実際の生徒の図面では、まだためしていません。思ったように読まれないときは、かくれ線をかきたすか、設定を「全部かく」にしてください。
- かくれ線を全部かいても、第三角法の3つの図だけでは形が1つに決まらないことがあります（例：正面・上・右のどこからも面が見えない背板が「ある」か「ない」か）。そのときは自然なほう（たな板が板1枚分手前で止まっていれば、背板があるほう）を先に出し、「ほかの形を見る」ボタンで切りかえられます。
- 写真の読み取りは、紙の傾き・回転・ピントのあまさ・白黒印刷などを模した**擬似的な写真**で確認しています。実際の教室の写真（かげ、うすいえんぴつ、紙のそり）では読みまちがいが出ることがあります。その場合は画面で直せます。
- 読みこめるのは画像（JPEG / PNG など）です。スキャナの PDF はそのままでは読めません。
- STL は実物大（mm）です。3Dプリンタに入らないときは、スライサーソフトで縮小してください。

## 開発者向け

```
npm install          # three.js（3D表示）, esbuild（ビルド）, playwright（ブラウザ確認）
npm run build        # src/ → dist/index.html（1ファイル）, dist/artifact.html
npm test             # エンジン・読み取り・保存形式のテスト（Node だけで動く）
npm run e2e          # ビルドして、ヘッドレス Chromium で通し確認
```

`npm run e2e` には Chromium が必要です（`npx playwright install chromium`）。
OS にライブラリ（libnss3, libnspr4, libasound2）が入っていないときは `sudo npx playwright install-deps chromium` を実行するか、
ライブラリを取り出したフォルダを環境変数 `CHROMIUM_LIBS` に指定します。`OFFLINE=1` をつけると、ネットワークを切った状態で確認します。

| 場所 | 内容 |
|---|---|
| `src/core/` | 図面 → 立体のエンジン。`render.js`（立体から3つの図をかく）、`solver.js`（図から立体をさがす）、`lenient.js`（かくれ線がはぶかれた図面から、板の組み合わせをさがす）、`boards.js`（板かどうか）、`analyze.js`（点検の流れ）、`messages.js`（生徒に伝えることば）、`ruler.js`（マス → mm の読みかえと、入れた数字のあつかい）、`mesh.js`（3D の面・STL） |
| `src/sheet/` | 方眼用紙。`templates.js`（用紙の種類と寸法）、`layout.js`（用紙の中身 → SVG）、`code.js`（設定コード）、`pdf.js` |
| `src/reader/` | 写真の読み取り。マーク検出 → 補正 → 線分ごとの判定 |
| `src/ui/` | 画面。`editor.js`（図面エディタ）、`viewer3d.js`（3D ビュー・GLB）、`save.js`（保存） |
| `test/` | テスト。`designs.js` は、よくある作品18種類。`synth.js` は、用紙にえんぴつでかいて撮影した「擬似的な写真」をつくる道具 |

公開ページ（GitHub Pages）は、`main` ブランチの中身をそのまま配信しています。フォルダ直下の `index.html` は入口で、`dist/index.html` へ送るだけです。
`src/` を変えたら `npm run build` をして、`dist/` もいっしょにコミットしてください（push すると数分で公開ページに反映されます）。

`dist/artifact.html` は、claude.ai のアーティファクトとして公開するときの形です。その画面ではページから直接ダウンロードできないため、
印刷ボタンは出さず、STL / GLB は ZIP に入れて保存します（アプリ本体 `dist/index.html` では、そのまま `.stl` / `.glb` で保存されます）。
